# Assurance extension uses a versioned Registry

Built-in and host-provided Assurance Requirement kinds are registered under namespaced, versioned identifiers with strict Evidence Contracts, evaluator ownership, independence rules, and Artifact Budgets, and their resolved definitions are frozen into Effective Policy. Planner may activate registered requirements but cannot invent executable assurance semantics; an unknown kind blocks the Mission. This permits ecosystem extension without allowing prompt text to redefine what the Quality Gate means.

Registration is accepted only during host startup and plugin composition. Duplicate identities or versions fail startup, and each Mission freezes the exact provider and definition digests it uses; if a required Assurance Provider is unavailable on recovery, the Mission blocks rather than skipping or substituting the evaluator.
